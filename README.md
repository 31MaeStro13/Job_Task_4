# AI-помощник для подготовки B2B-карточек товаров (КИПиА)

Сервис автоматизированной подготовки черновиков товарных карточек для промышленного B2B-каталога контрольно-измерительных приборов и автоматики. Входные технические спецификации преобразуются в структурированные описания, оптимизированные под поисковые системы и работу менеджеров по закупкам.

Решение построено на связке фреймворка Agno, валидации схем через Pydantic v2 (Structured Outputs) и LLM API (Google Gemini / OpenAI).

---

## Архитектура и функционал

Сервис решает четыре прикладные задачи контент-отдела:

1. **Соблюдение регламентов B2B-каталога**:
   - SEO-заголовок строго до 70 символов.
   - Описание товара в диапазоне 800–1200 символов с пробелами.
   - Подбор 3–5 точных поисковых запросов для промышленного сегмента (модель, ГОСТ/ТУ, типоразмер, давление).
   - Коммерческий блок: сегментация целевой аудитории (ЖКХ, нефтегаз, теплоэнергетика) и список решаемых инженерных задач.

2. **Защита от галлюцинаций (Zero-Hallucination)**:
   - Модели запрещено додумывать численные значения и технические параметры.
   - Если характеристика отсутствует во входных спецификациях (например, межповерочный интервал или температурный диапазон), в таблице выставляется статус `«данных нет»`.

3. **Двухуровневый аудит полноты данных**:
   - Детерминированный скрипт (`app/validator.py`) сканирует критические для КИПиА атрибуты: присоединение, питание, выходной сигнал, защита IP, температурный диапазон.
   - Модель формирует прикладной чек-лист для контент-менеджера с перечнем параметров, которые необходимо запросить у поставщика или найти в заводском паспорте прибора.

4. **Мультиформатный экспорт**:
   - Выдача результата в Markdown (для рендеринга на витрине), JSON (для импорта в CMS/PIM) и чистом тексте.
   - Управление как через CLI (поддерживает пайплайны Linux), так и через интерактивную веб-панель Streamlit.

## Установка и запуск

### 1. Подготовка окружения через uv
В проекте используется менеджер пакетов `uv` (требуется Python 3.12+):

```bash
cd Job_Task_4
uv sync
```

### 2. Конфигурация API
Создайте файл переменных окружения на основе примера:
```bash
cp .env.example .env
```

Заполните параметры в `.env`. По умолчанию настроен провайдер Gemini:
```ini
LLM_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ_gemini
GEMINI_MODEL=gemini-2.5-flash

# Альтернативный провайдер (OpenAI):
# LLM_PROVIDER=openai
# OPENAI_API_KEY=ваш_ключ_openai
# OPENAI_MODEL=gpt-4o-mini
```

## Варианты использования

### Работа через консоль (CLI)

Вывод готовой карточки в формате Markdown в терминал:
```bash
uv run python main.py data/product_1.json
```

Сохранение карточки в файл:
```bash
uv run python main.py data/product_1.json -o output.md
```

Получение сырого структурированного JSON:
```bash
uv run python main.py data/product_1.json --format json
```

Обработка через стандартный поток ввода (stdin):
```bash
cat data/product_2.json | uv run python main.py --format text
```

### Интерактивный веб-интерфейс (Streamlit)
Для визуальной работы контент-менеджера предусмотрена веб-панель:
```bash
uv run streamlit run app/web.py
```
После запуска интерфейс доступен по адресу `http://localhost:8501`. В приложении реализованы:
- Переключение провайдеров (Gemini / OpenAI).
- Быстрый выбор тестовых приборов из выпадающего списка или вставка произвольного JSON.
- Онлайн-счетчики длины заголовка (лимит 70) и описания (норма 800–1200) с цветовой индикацией.
- Вкладки предварительного просмотра и кнопки скачивания файлов в `.md`, `.json` и `.txt`.

### Запуск тестов
```bash
uv run pytest
```

## Обоснование инженерных решений и промпт-инжиниринг

1. **Гарантированная структура (Structured Outputs)**. 
   Вместо извлечения JSON из свободных текстовых ответов через регулярные выражения, фреймворк Agno принудительно валидирует ответ модели по схеме Pydantic `ProductCardOutput`. Это исключает поломку синтаксиса и гарантирует наличие всех требуемых полей на уровне протокола LLM.

2. **Отказоустойчивость вызовов (Resilience Harness)**.
   В `app/agent.py` реализован механизм повторных попыток с экспоненциальной задержкой и автоматическим переключением на резервную модель (`gemini-2.5-flash-lite`) при временных сбоях API или ошибках вида 503 UNAVAILABLE.

3. **Предотвращение галлюцинаций**.
   Системный промпт жестко разграничивает копирайтинг и технические факты. Модели разрешено адаптировать формулировки назначения прибора для B2B-аудитории, но строго запрещено экстраполировать характеристики (класс точности, резьбу, напряжение). Все не указанные во входе параметры фиксируются как `«данных нет»`.

4. **Комбинированный валидатор**.
   Поверх генерации работает независимый код (`app/validator.py`). Он проверяет фактические границы длины строк и проводит детерминированный аудит по справочнику ключевых узлов КИПиА, дополняя выводы нейросети.

## Ограничения прототипа и направления развития

- **Потоковая генерация (Streaming)**: добавление SSE-стриминга в интерфейс для снижения времени первого отклика (TTFT).
- **Массовая обработка (Batching)**: подключение Celery и Redis для фонового парсинга и генерации каталогов на тысячи позиций из Excel/CSV.
- **Интеграция с каталогами**: экспорт карточек напрямую в базы данных CMS/PIM (1С, Bitrix, Commercetools) по API.
- **Автоматизированная оценка качества (LLM Evals)**: внедрение этапа автоматической проверки сгенерированного текста на соответствие исходному паспорту изделия с расчетом метрики точности фактов (Faithfulness).
