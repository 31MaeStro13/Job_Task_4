# Генератор карточек КИПиА на базе LLM (B2B E-commerce)

Прототип сервиса для контент-менеджеров промышленных каталогов. На входе — сырые обрывки паспорта прибора или технические характеристики в JSON. На выходе — готовый черновик карточки для B2B-витрины: выверенный SEO-заголовок, связное описание без «воды», таблица параметров с отсечкой домыслов и чек-лист недостающих данных.

В основе пайплайна: фреймворк Agno, схемы Pydantic v2 со Structured Outputs и модели Google Gemini (с возможностью переключения на OpenAI).

---

## Как устроена логика обработки

Автоматизировать заполнение инженерного каталога сложнее, чем обычный e-commerce. Главная проблема больших языковых моделей в этой задаче — склонность додумывать цифры и неспособность точно считать символы. Языковая модель оперирует BPE-токенами, поэтому запрос «напиши ровно 900 символов» без внешнего контроля неизбежно плывет по границам.

Чтобы получить стабильный результат для отдела контента, пайплайн разбит на три независимых слоя:

### 1. Защита от галлюцинаций (Zero-Hallucination)
В промпте действует жесткий запрет на экстраполяцию технических параметров. Резьба, рабочее давление, погрешность и выходной сигнал берутся только из входного файла. Если параметр критичен для прибора, но поставщик его не указал, поле не выдумывается, а получает статус `«данных нет»`. 

Входные пользовательские данные изолируются внутри XML-тегов `<raw_instrument_data>`, что исключает влияние неструктурированного текста на системные инструкции агента.

### 2. Двухконтурный поиск пропущенных характеристик
Контент-менеджеру важно сразу видеть, что нужно запросить у завода-изготовителя. Анализ неполноты данных идет параллельно:
* **Детерминированный сканер (`app/validator.py`)**: код на регулярных выражениях и ключевых маркерах проверяет обязательный отраслевой минимум для КИПиА (наличие присоединения, питания, температурных рамок и выходного сигнала).
* **Семантический анализ модели**: агент оценивает контекст прибора целиком и подсвечивает специфичные пропуски (например, взрывозащиту, класс IP или межповерочный интервал). На выходе оба списка объединяются и дедуплицируются.

### 3. Гарантия схемы и отказоустойчивость сети (Resilience)
От парсинга ответов модели через regex отказались сразу. Агент Agno возвращает строго типизированный объект `ProductCardOutput` через нативный механизм JSON Schema. 

При обращении к бесплатным и стандартным тарифам Gemini API часто возвращает `503 UNAVAILABLE` из-за всплесков нагрузки. Чтобы сервис не падал перед пользователем, вызовы обернуты в цикл повторных попыток: скрипт применяет экспоненциальную задержку и при повторном сбое прозрачно переключается на резервную модель `gemini-3.5-flash-lite`.

## Быстрый старт

Проект разворачивается через пакетный менеджер `uv` под Python 3.12+:

```bash
# 1. Установка окружения и библиотек
uv sync

# 2. Настройка ключа API
cp .env.example .env
```

В `.env` достаточно указать рабочий API-ключ Gemini (или OpenAI):
```ini
LLM_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ_здесь
GEMINI_MODEL=gemini-3.5-flash
```

## Сценарии использования

### 1. Веб-интерфейс для контент-менеджера (Streamlit)
Самый наглядный способ работы — запуск локальной панели:
```bash
uv run streamlit run app/web.py
```
В браузере по адресу `http://localhost:8501` доступно:
* Быстрый выбор тестовых приборов из выпадающего списка (`product_1.json`, `product_2.json`, `product_3.json`) или вставка произвольного JSON.
* Цветовые индикаторы регламентов ТЗ: длина SEO Title ($\le 70$ символов) и описания ($800–1200$ знаков с пробелами) считаются на лету.
* Вкладки с готовым Markdown, чистым текстом и JSON, а также кнопка мгновенного скачивания файла.

### 2. Консольный режим (CLI)
Подходит для встраивания в скрипты автоматизации и конвейеры:
```bash
# Вывод карточки в Markdown
uv run python main.py data/product_1.json

# Сохранение в файл
uv run python main.py data/product_1.json -o card.md

# Получение сырого JSON для интеграции
uv run python main.py data/product_2.json --format json

# Передача через пайплайн stdin
cat data/product_3.json | uv run python main.py --format text
```

### 3. Запуск тестов
```bash
uv run pytest
```
Тестовый набор проверяет работу Pydantic-схем, корректность отсечки переполненных входных данных, точность детерминированного валидатора и экспорт во все форматы.

## Практические ограничения и развитие в прод

В рамках тестового задания решение реализовано как компактный прототип. Для перевода сервиса в промышленную эксплуатацию с каталогами на десятки тысяч позиций заложены следующие точки роста:

1. **Асинхронные очереди (Celery / Redis)**: при пакетной загрузке прайс-листов от поставщиков синхронный вызов блокирует поток. Нужен пул фоновых воркеров с контролем лимитов провайдера (Rate Limits).
2. **Стриминг ответов (SSE)**: для снижения времени первого отклика в веб-интерфейсе целесообразно отдавать текст потоком по мере генерации токенов.
3. **Прямой коннектор к PIM/ERP**: отправка верифицированных карточек напрямую в базу данных интернет-магазина через вебхуки или REST API 1С / Bitrix.
4. **Контур автоматической оценки (Evals)**: внедрение этапа LLM-as-a-Judge с метрикой фактологической точности (Faithfulness), сопоставляющей текст черновика с исходным PDF-паспортом прибора.
