# ⚙️ AI-помощник для подготовки B2B-карточек товаров (КИПиА)

Прототип сервиса автоматической генерации черновиков карточек товаров для промышленного B2B-каталога контрольно-измерительных приборов и автоматики (КИПиА). 

Построен на базе **Agno Agent Framework**, **Pydantic v2** (Structured Outputs) и современных LLM API (**Google Gemini** / **OpenAI**).

---

## 🎯 Решаемые задачи
1. **Строгие лимиты ТЗ**:
   - SEO-заголовок (до 70 символов).
   - SEO-описание (целевой объем 800–1200 символов).
   - 3–5 целевых поисковых запросов под B2B SEO (Яндекс/Google).
   - Commercial-блок для отдела продаж (целевая аудитория и прикладные задачи).
2. **Zero-Hallucination (Полный запрет на выдумку характеристик)**:
   - Значения параметров берутся **строго** из входных данных.
   - Если характеристика важна для прибора, но отсутствует во входе — явно проставляется метка `«данных нет»`.
3. **Двухконтурный контроль неполных данных**:
   - Детерминированный анализатор базовых параметров КИПиА (`app/validator.py`).
   - Семантический анализ пропусков моделью с формированием чек-листа для менеджера по закупкам.
4. **Удобство копирования**:
   - Вывод в форматах **Markdown**, **JSON** и **Plain Text**.
   - Доступен как через **CLI**, так и через наглядный **Web-интерфейс (Streamlit)**.

## 🚀 Быстрый старт

### 1. Установка окружения (через `uv`)
Проект оптимизирован под быстрый и воспроизводимый запуск с помощью `uv` (Python 3.12+):

```bash
# Клонирование репозитория и переход в директорию
cd Job_Task_4

# Установка всех зависимостей в изолированное виртуальное окружение
uv sync
```

### 2. Настройка API-ключей
Скопируйте шаблон переменных окружения:
```bash
cp .env.example .env
```
Укажите ваш API-ключ в файле `.env`:
```ini
LLM_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ_gemini
GEMINI_MODEL=gemini-3.5-flash

# Либо для OpenAI:
# LLM_PROVIDER=openai
# OPENAI_API_KEY=ваш_ключ_openai
# OPENAI_MODEL=gpt-4o-mini
```

## 💻 Использование

### 1. Запуск через CLI
Генерация карточки в формате Markdown с выводом в консоль:
```bash
uv run python main.py data/product_1.json
```

Сохранение результата в файл:
```bash
uv run python main.py data/product_1.json -o output.md
```

Вывод в формате JSON:
```bash
uv run python main.py data/product_1.json --format json
```

Передача данных через конвейер (stdin):
```bash
cat data/product_2.json | uv run python main.py --format text
```

### 2. Запуск локального Web-интерфейса (Streamlit)
```bash
uv run streamlit run app/web.py
```
Интерфейс доступен в браузере по адресу `http://localhost:8501`:
* Выбор провайдера (Gemini / OpenAI).
* Быстрая загрузка готовых пресетов или вставка своего JSON.
* Индикаторы соблюдения лимитов символов (Title <= 70, Desc 800-1200) в реальном времени.
* Вкладки с Markdown, JSON, текстом и кнопки скачивания.

### 3. Запуск тестов
```bash
uv run pytest
```

## 🧠 Принятые решения и промпт-инжиниринг

1. **Гарантия валидности схемы (Agno + Structured Outputs)**:
   Вместо ненадежного парсинга текста регулярными выражениями или ожидания JSON из markdown-блоков, агент Agno принудительно возвращает типизированный объект `ProductCardOutput` через JSON Schema. Это исключает синтаксические ошибки JSON на 100%.

2. **Защита от галлюцинаций (Zero-Hallucination Guardrails)**:
   В системном промпте задана жесткая директива: все технические характеристики извлекаются исключительно из переданного JSON. Если параметр не указан, модель обязана выставить значение `«данных нет»`.
   В `ProductCardOutput` используется структура `List[SpecItem]`, что предотвращает потерю ключей или генерацию фиктивных полей.

3. **Детерминированный контроль качества (Validator)**:
   Поверх генерации модели работает модуль `app/validator.py`:
   - Подсчитывает фактическую длину заголовка и описания, сигнализируя при выходе за рамки ТЗ.
   - Анализирует состав технических параметров на предмет отраслевых пропусков (наличие присоединения, питания, интерфейса, температурного диапазона).

## ⚖️ Ограничения текущего прототипа и точки роста

### Ограничения MVP:
* Синхронная пакетная обработка (поштучная подача товаров).
* Фиксированный список базовых параметров КИПиА в эвристическом валидаторе.

### План дальнейших улучшений (Production Ready):
1. **Streaming-генерация**: потоковая передача текста в веб-интерфейс для мгновенного отклика (time-to-first-token < 1 сек).
2. **Batch Processing / Асинхронные очереди**: фоновая обработка каталогов на тысячи позиций через Celery/Redis или асинхронные воркеры.
3. **Интеграция с ERP / PIM**: экспорт готовых карточек напрямую в 1С:Предприятие, Bitrix24 или OpenCart через REST API / Webhooks.
4. **Контур LLM-as-a-Judge (Evals)**: авто-проверка фактологической точности карточки относительно паспорта изделия с расчетом метрики Faithfulness (Zero Hallucination Score).
